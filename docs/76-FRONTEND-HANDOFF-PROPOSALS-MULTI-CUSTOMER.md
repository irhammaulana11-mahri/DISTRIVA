# Serah terima frontend — usulan dengan banyak pelanggan (docs/62 §37)
Backend siap di kode (tes lulus); migrasi 200000 belum diterapkan ke `distriva_db`. Kontrak: docs/57 "Usulan dengan banyak pelanggan".
## Perubahan alur pembuatan usulan (halaman PB/PD, tahap 1)
- Tombol **Buat Usulan** membuka layar pemilihan; **sebelum itu tidak ada tabel data pelanggan yang ditampilkan** di layar usulan. Setelah mulai membuat usulan tampil **tabel pelanggan** dari `GET /proposals/selectable` (hanya 3 fasa ≥ 6600 VA, ULP pengguna, belum pada usulan lain) dengan **kotak cari/dropdown** (nama, IDPEL, nomor permohonan, alamat; paginasi). Pengguna mencentang satu atau banyak pelanggan; **yang pertama dipilih menjadi pelanggan utama (perwakilan)** — tampilkan penanda dan izinkan mengganti urutan sebelum menyimpan; judul usulan opsional; **Simpan** → `POST /proposals`.
- Pelanggan 1 fasa tidak muncul di tabel (dihitung lewat blok SR-APP pada gambar); data mereka tetap ada di database.
- **Halaman daftar PB/PD** memanggil `GET /applications?listing=pbpd`: memuat permohonan **manual** (semua daya) dan **pelanggan utama usulan**; permohonan hasil sinkronisasi yang belum menjadi usulan tersimpan tetapi tidak tampil di halaman ini. Tampilkan kolom `proposal_number` (tautan ke usulan) dan `source_type`. Nomor usulan berformat `00001/USULAN-PBPD/07-11/kode-unit/2026`.
## Halaman usulan
Detail usulan (`GET /proposals/{id}`): nomor, daftar anggota (nama, IDPEL, tarif, daya, biaya, status), riwayat; **tambah anggota** (tabel pilihan yang sama + alasan), **keluarkan anggota** (alasan; perwakilan tidak bisa), **batalkan usulan** (alasan); kunci perubahan setelah WO terbit (backend 409). Tautan **"Lanjutkan"** ke survey/gambar/MTO/RAB/WO **memakai `representative_application_id`**: seluruh halaman tahap lanjutan membuka permohonan perwakilan dan menampilkan banner "Usulan {nomor}: {n} pelanggan". Tombol survey/gambar pada anggota non-perwakilan dinonaktifkan (backend 409).
## KKF
Panel KKF pada halaman usulan memakai `POST /proposals/{id}/kkf-runs` (dry run → simpan) dan `GET /proposals/{id}/kkf-runs`; tampilkan rincian per anggota dari `sources.members[]` (tarif, daya, jam nyala, harga, biaya penyambungan, jenis meter), hasil agregat, dan input `previous_meter_payment` per anggota bila backend meminta (409). Dokumen KKF (docs/70) memuat tabel pelanggan.
## Aturan UI dan tes
Fail-closed menurut `proposals.*`, `kkf.*`; pesan 403/404/409/422 apa adanya. Tes Vitest: tabel pilihan tidak menampilkan data sebelum "Buat Usulan", pencarian, urutan perwakilan, banner usulan, panel KKF per anggota.
