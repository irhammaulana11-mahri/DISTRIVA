## 1. Konvensi

- Basis: `/api`. JSON saja: kirim `Accept: application/json` dan `Content-Type: application/json`. Nilai tanggal `Y-m-d`; waktu ISO 8601 / `timestamptz` (zona waktu bisnis `Asia/Jakarta`, penyimpanan UTC).
- **Autentikasi:** `Authorization: Bearer <token>` (Sanctum). Token berlaku **30 menit idle** (diperpanjang tiap request). Token dari `POST /auth/login`; disimpan frontend di `sessionStorage`.
- **Rute terlindungi** menjalankan `auth:sanctum` + `EnsureActiveAccount`: tanpa/invalid/kedaluwarsa token → `401 {"message":"Unauthenticated."}`; akun bukan `ACTIVE` → `403 {"message":"Akun tidak aktif."}`.
- **Kode status:** `200` berhasil · `201` dibuat · `202` diterima (OTP request) · `401` tidak terautentikasi · `403` tidak berwenang / dilarang aturan · `404` **tidak ditemukan atau di luar scope** (sengaja tidak dibedakan) · `409` pelanggaran aturan domain (overlap, admin terakhir, sudah diakhiri, dll.) · `422` validasi · `429` pembatas laju · `503` layanan tidak tersedia.
- **Format error:** `{"message":"…"}`; validasi 422: `{"message":"…","errors":{"field":["pesan", …]}}` (pesan Indonesia untuk aturan DISTRIVA, bahasa Inggris untuk aturan bawaan Laravel).
- **Hak akses diperiksa server pada setiap request.** `GET /admin/access` hanya petunjuk untuk UI.
- **Paginasi (daftar admin):** query `page`, `per_page` (1–100, default 15). Respons `{"data":[…],"meta":{"current_page","per_page","total","last_page"}}`. Scope diterapkan **sebelum** hitung/paginasi (total tidak membocorkan data di luar scope).
- **Pembatas laju** (per menit): login 10/alamat+IP (30/IP), `otp-request` 10/IP (+5/jam per alamat email), `otp-verify` 10/alamat+IP, `password-change` 5/user, `admin` 60/user. Terlampaui → `429`.
- Rahasia tidak pernah ada di respons: password, hash, token lain, kode OTP, nomor telepon dalam laporan pengiriman.

**Kebijakan password (doc 16):** min 8 karakter, huruf besar+kecil, angka, simbol; tidak sama dengan 5 password terakhir; bukan password umum; tidak memuat nama (≥4 huruf) atau bagian email. Semua pelanggaran dikembalikan sekaligus.
**OTP:** 6 digit, berlaku 10 menit, 5 tebakan salah membatalkan kode, jeda kirim ulang 60 dtk, kode dikirim ke **semua kanal tersedia** (email + WhatsApp) setelah respons HTTP.
**Status akun:** `PENDING_ACTIVATION` (belum aktivasi; tanpa password) → `ACTIVE`; `SUSPENDED`/`INACTIVE` hanya diubah administrator dan **tidak** dapat memakai OTP.

## 3f. MTO per versi gambar (tahap 4A) — token + akun ACTIVE + hak; scope mengikuti ULP permohonan

- Berkas gambar (`POST /drawings/{id}/versions/{v}/documents`): judul dan nama berkas dibuat server `GBR_{No. Agenda}_{Nama Pelanggan}` (lampiran ` - Lampiran n`); field `title` dari klien diabaikan.

## Rantai survei Manager ULP, KKO per fasa (docs/82 §12)
- `POST /surveys/{id}/versions/{v}/decisions` {step: ULP_MANAGER}: APPROVED langsung `ACCEPTED` (`result.survey_status`), tanpa langkah UP3/Asman; langkah lain → 409. Gambar yang ikut survei dilepas dan lanjut di Review UP3 rantai gambar. `short_chain` selalu `true`.
- Isi survei: `sr_length_m` (meter) baru; `network_distance_m` = jarak bangunan dari tiang eksisting; keduanya wajib saat `submit` (409 "lengkapi: panjang SR yang dibutuhkan, jarak bangunan dari tiang eksisting"). `survey_date` terisi otomatis hari berjalan saat versi dibuat.
- `PUT /applications/{id}/kko` menerima `phase_detail` {gtt:{jurusan_count, jurusan_length_km, distance_gtt_km, conductor, loading_pattern}, load:{r,s,t}, jurusan:[{name,r,s,t}], base_voltage:{r,s,t}, existing_voltage:{r,s,t}, plan:{sutm_km, mvtic_km, xlpe_km, trafo_mgmt_set, gtt_sisipan_bh, sutr_km, rehab_sutr_km}, added:{r,s,t}, after_existing_voltage:{r,s,t}, notes}. Bila `load` lengkap, server menghitung `measured_load_kva`, `loading_before_pct`, `loading_after_pct`, kelas, dan `voltage_location_v` (terendah dari `existing_voltage`). Respons `record.phase_detail` dan `record.phase_result` {before, after: {loads, max_a, voltage_ref_v, load_kva, loading_pct, imbalance_pct}}.
- `GET /applications/{id}/kko/baseline?substation_id=` (izin `kko.record`) → `{data:{substation:{id,code,name,capacity_kva}, reading:{current_r_a,s,t, base_voltage_r_v,s,t, feeders:[{label,current_r_a,current_s_a,current_t_a}], …}|null, added_power_kva, suggested_added:{r,s,t}}}`.
- Tegangan ujung gardu tidak lagi mengisi `voltage_location_v` secara otomatis (tegangan eksisting pelanggan diisi surveyor).

## Usulan dibuat setelah survei, gambar milik usulan (docs/82 §14)
- `POST /proposals/issue` {application_id} (izin `proposals.manage`, unit permohonan) → 201 `{data:{id, proposal_number}}`; 409: survei belum `ACCEPTED`, hasil bukan perlu perluasan, usulan sudah dibuat, atau permohonan anggota non-perwakilan.
- Keputusan survei tidak menerbitkan nomor usulan (`result.proposal_issued` dihapus). `POST /applications/{id}/drawing`: 409 sampai survei disetujui dengan `requires_drawing` **dan** usulan bernomor ada; gambar tidak lagi ikut survei (`with_survey` selalu false).
