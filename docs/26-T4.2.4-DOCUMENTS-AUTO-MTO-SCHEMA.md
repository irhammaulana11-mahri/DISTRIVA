# 26 — T4.2.4 Database Schema: Dokumen, Review, dan Auto MTO

**Dokumentasi:** DISTRIVA v3.2 — 5 November 2026  
**Status:** DESAIN DIREVISI DAN VALIDASI STRUKTURAL; belum migration/implementasi.

## 1. Ruang lingkup dan prinsip

T4.2.4 mengelola identitas dokumen, versi file immutable, persyaratan dokumen, workflow review, paket Auto MTO, pemrosesan file oleh Python, hasil ekstraksi, koreksi teknis, kebutuhan material hasil BOM, verifikasi dan snapshot persetujuan. Tabel `applications`, `users`, `organizational_units`, `roles`, `materials`, `units_of_measure`, `khs_items`, `khs_item_versions`, `bom_headers`, `bom_items`, dan `bom_formula_definitions` adalah dependency lintas domain; tidak dibuat ulang di sini.

- Satu kategori dapat memiliki banyak dokumen; satu dokumen logis memiliki satu identitas dan banyak versi.
- `application_documents.current_version_id` adalah satu-satunya pointer versi terkini. Tidak ada `is_current` pada versi.
- Setiap revisi membuat versi baru; versi lama tetap dapat dibaca sesuai policy, tidak dapat ditimpa, dan approval lama tidak diwariskan.
- Lifecycle file dipisahkan dari keputusan review. Keputusan disimpan di cycle/assignment.
- Storage private di luar public web root. Laravel mengotorisasi akses; Python menerima akses sementara melalui API/token bertenggat, bukan akses DB/file system langsung.
- Satu paket Auto MTO dapat menggabungkan beberapa file terkait. Kegagalan satu file tidak menghentikan file lain; retry hanya file gagal.
- AI/OCR/CV/CAD menghasilkan kandidat, bukan keputusan. Confidence tidak sama dengan approval.
- Tidak ada fuzzy guessing untuk KHS yang tidak ditemukan; harus dipilih manual.
- RAB/KKF approval khusus tetap mengikuti T3.6, bukan generic document workflow.

## 2. Integritas lintas domain yang wajib

1. `application_documents.application_id` → `applications.id`.
2. Versi file menunjuk dokumen pemilik melalui composite FK `(document_id, previous_version_id)` → `(document_id, id)`; versi tidak dapat berpindah dokumen.
3. `application_documents.current_version_id` composite FK `(id,current_version_id)` → versi `(document_id,id)` memastikan pointer milik dokumen yang sama.
4. Paket dan seluruh dokumen/versi harus berasal dari aplikasi yang sama. `auto_mto_package_documents` menyimpan `application_id` sebagai FK dan composite FK ke `application_documents` serta `application_document_versions`.
5. File job harus berasal dari paket yang sama; job-file mengikat `(processing_job_id, package_id)` dan `(package_id, package_document_id, document_version_id)`.
6. Token mengikat job, job-file, dan attempt yang sama; token hanya hash yang disimpan, bukan token mentah.
7. Hasil dan ekstraksi mengikat attempt yang sama.
8. KHS item dan versinya harus konsisten; satuan menggunakan `units_of_measure`.
9. Kebutuhan material mengikat BOM header, BOM item, formula, material, dan satuan yang konsisten. Nilai formula/koefisien dan input penting disnapshot untuk reproduksibilitas.
10. Verifikasi item/material requirement harus milik paket yang sama.
11. Approval history hanya dapat mengesahkan snapshot milik paket yang sama.
12. Stage review menyimpan snapshot actor rules (role, unit scope, jumlah minimum approval, decision_required). Assignment merujuk actor snapshot tersebut.

## 3. Entitas dan tabel

### 3.1 Kategori, persyaratan, dan kepatuhan
- `document_categories`: kode unik, nama, ekstensi yang diizinkan, versioning, aktif.
- `document_requirements`: kategori, tipe PB/PD atau semua, tahap proses, kondisi, wajib/tidak, jumlah file minimum/maksimum, ekstensi override.
- `document_requirement_compliances`: status pemenuhan per aplikasi dan requirement; `PENDING`, `FULFILLED`, `NOT_APPLICABLE`, `REJECTED`; pemeriksa, waktu, catatan.

Kategori: `APPLICATION`, `SURVEY`, `TECHNICAL_DRAWING`, `RAB_KKF`, `FEASIBILITY_STUDY`, `REGISTRATION`, `PAYMENT`, `WORK_ORDER`, `CONSTRUCTION`, `METER_INSTALLATION`, `COMPLETION`, `OTHER`. Syarat kondisional hanya wajib jika kondisi proses benar.

### 3.2 Dokumen dan versi
- `document_storage_locations`: storage private `LOCAL_PRIVATE` atau `OBJECT_PRIVATE`; root/key tidak diekspos ke klien.
- `application_documents`: identitas logis dokumen, aplikasi, kategori, requirement opsional, document_code unik, title, `current_version_id`, status agregat, creator.
- `application_document_versions`: nomor versi, previous_version_id, original/stored filename, storage location/key, MIME, extension, byte size, SHA-256, revision reason, lifecycle status, uploader/time.
- `document_access_logs`: actor user/service, versi spesifik, action VIEW/DOWNLOAD/PREVIEW, source/reference/time, metadata.

Lifecycle versi: `UPLOADED`, `SUPERSEDED`, `ARCHIVED`, `QUARANTINED`, `REJECTED` (sesuaikan proses scanning). Review decision tidak disimpan sebagai lifecycle file. Versi lama tidak dihapus saat versi baru diunggah.

### 3.3 Workflow dan review
- `document_workflow_templates`: kode, versi, status, masa berlaku, creator/approver.
- `document_workflow_rules`: kategori, tipe aplikasi, tahap proses, kondisi dan template; aturan aktif tidak boleh ambigu/overlap untuk kombinasi kunci yang sama.
- `document_workflow_stages`: tahap, urutan, REVIEW/APPROVAL, SEQUENTIAL/PARALLEL, wajib.
- `document_workflow_stage_actors`: actor rule berupa role, unit scope ULP/UP3/GLOBAL, decision_required, minimum_approvals.
- `document_review_cycles`: review atas satu versi dokumen, template dan versinya disnapshot, nomor cycle, status dan creator.
- `document_review_cycle_stages`: snapshot tahap workflow.
- `document_review_cycle_stage_actors`: snapshot actor rules pada saat cycle dibuat, termasuk role, unit scope, decision_required, minimum_approvals.
- `document_review_assignments`: reviewer, actor snapshot, role/unit snapshot, review type, status/decision, timestamps, notes.
- `document_review_comments`: komentar umum/revisi/approval dan source locator.

Setiap versi baru memulai cycle baru. Jika salah satu reviewer meminta revisi, versi baru memerlukan review ulang; approval versi sebelumnya tetap sebagai histori, bukan approval versi baru. `document_reviews` dan `document_revision_histories` terpisah tidak dibuat karena fungsinya sudah ditampung oleh cycle, assignment, comments, `previous_version_id`, dan `revision_reason`.

### 3.4 Auto MTO
- `auto_mto_packages`: satu paket per aplikasi dan nomor/versi paket; `previous_package_id` dibatasi pada aplikasi sama.
- `auto_mto_package_documents`: file dan versi yang disertakan, role, urutan, primary/required/priority; semua dari aplikasi yang sama.
- `auto_mto_processing_jobs`: job INITIAL/RETRY/REPROCESS, parent job, engine, status, waktu dan error.
- `auto_mto_processing_job_files`: file per job, status, attempt count, checksum, error; package/document/version harus cocok.
- `auto_mto_processing_file_attempts`: nomor attempt, status, waktu, error dan checksum input/output.
- `auto_mto_file_access_tokens`: hash token sementara, job/file/attempt, scope DOWNLOAD, expiry/revocation/use.
- `auto_mto_processing_results`: hasil per attempt, checksum, engine, status dan metadata.
- `auto_mto_extractions`: kandidat KHS/simbol/kuantitas/unit, source locator, confidence, raw result.
- `auto_mto_items`: item KHS per paket, KHS identity dan version, code/description snapshot, PSG/BKR, detected/verified qty and unit, calculation source, verification/item status.
- `auto_mto_item_sources`: relasi item dengan ekstraksi (PRIMARY/SUPPORTING/CONFLICT).
- `auto_mto_item_revisions`: jejak ADD/UPDATE/REMOVE dengan before/after, reason, actor/time.
- `auto_mto_material_requirements`: hasil deterministic BOM dari item, material, BOM version/item/formula, formula snapshot, quantities, unit, calculation/verification/item status.
- `auto_mto_material_requirement_revisions`: revisi kebutuhan material beserta alasan/actor.
- `auto_mto_verifications`: verifikasi item atau kebutuhan material; tepat satu target wajib diisi dan target harus berada pada paket yang sama.
- `auto_mto_package_snapshots`: snapshot VERIFIED/APPROVAL, data JSONB, hash, creator/time.
- `auto_mto_approval_histories`: keputusan ULP technical officer/Manager ULP pada snapshot spesifik; approver, role, unit, decision, notes/time.

## 4. Urutan approval dan proses

1. Dokumen gambar masuk sebagai versi baru.
2. Auto MTO memproses seluruh file paket secara independen. Python mengakses setiap file melalui token sementara.
3. Ekstraksi menghasilkan kandidat; Laravel menghitung kebutuhan melalui BOM dan formula terkontrol.
4. Petugas teknis ULP memeriksa/mengoreksi KHS, simbol, jumlah, satuan, menambah/menghapus item draft dengan alasan.
5. Snapshot VERIFIED dibuat; petugas teknis ULP memverifikasi item dan Manager ULP menyetujui snapshot MTO. Approval ini terpisah dari approval gambar.
6. Setelah itu gambar versi yang sama masuk review paralel Konstruksi UP3 dan Perencanaan UP3 sesuai T3.6. Manager ULP telah menyetujui submission ULP sebelum masuk antrian UP3.
7. Jika salah satu review meminta revisi, versi gambar/MTO baru dibuat sesuai dampak; kedua reviewer UP3 meninjau versi terbaru lagi. Approval lama historis.
8. Perubahan quantity/spec memicu recalc MTO/RAB/KKF; perubahan gambar yang tidak berdampak quantity/spec tetap direview tanpa recalc.
9. Kebutuhan material baru dikirim ke aplikasi material setelah WO disetujui ASMAN_KONSTRUKSI dan diterbitkan.

## 5. Constraint, indeks, trigger, dan kontrol aplikasi

### 5.1 Koreksi hasil audit struktural v3.2.1

- `document_workflow_rules` memiliki unique partial expression index untuk mencegah duplikasi rule aktif dengan key template/kategori/tipe/tahap/kondisi yang sama. Pemilihan rule lintas template yang masa berlakunya overlap tetap harus divalidasi oleh resolver Laravel; exclusion constraint temporal belum dipasang karena definisi prioritas dan kondisi bisnis belum final.
- `document_review_cycle_stage_actors.source_stage_actor_id` harus berasal dari `source_workflow_stage_id` pada cycle stage terkait; trigger `trg_cycle_actor_source` memvalidasi relasi tersebut.
- `auto_mto_extractions` membawa `package_id`; trigger `trg_extraction_package` memverifikasi bahwa paket cocok dengan jalur result → attempt → job file.
- `auto_mto_item_sources` membawa `package_id` dan composite FK untuk memastikan item serta extraction berasal dari paket yang sama.
- `auto_mto_package_documents` diberi unique index untuk urutan dokumen dalam paket dan satu dokumen utama per paket (jika `is_primary=true`).

### 5.2 Constraint, indeks, trigger, dan kontrol aplikasi

- Unique `(document_id, version_number)`, `(document_id,id)`, `(package_id, package_number, package_version)`, `(package_id, document_id, document_version_id)`, `(processing_job_id, package_document_id)`, `(job_file_id, attempt_number)`, `(cycle_id, cycle_number)`, `(template_id, version_number)`.
- `CHECK` untuk enum domain, nilai nonnegatif, ukuran file positif, version number/sequence positif, expiry token setelah created.
- Composite FK untuk semua relasi lintas package/document/version/job/attempt/snapshot.
- Partial unique indexes untuk satu versi current pointer ditangani FK; unique external code dan active rule per business key sesuai periode.
- Exclusion constraint temporal untuk template/rule aktif membutuhkan penetapan key bisnis dan PostgreSQL `btree_gist`; jangan pasang exclusion generik sebelum rule matching final disepakati.
- Trigger/service: parent version harus dokumen yang sama; package previous version same application; parent unit UP3/ULP rule inherited; immutable versions/snapshots/approval/audit; actor assignment must match cycle actor snapshot and scope; source workflow stage must belong to the cycle template; workflow cycle snapshots actors when instantiated; prevent hard-delete of referenced data.
- Laravel transaction: create version + update current pointer + start review cycle atomically; snapshot template/stages/actors; idempotent processing callback; lock row during version numbering; enforce same-application and same-package constraints before commit.
- File security: extension + MIME + signature, size, malware scan, safe filename, SHA-256; private download through policy; access logs; token hash only.

## 7. Hal yang tetap terbuka

- Format CAD/DWG/DXF yang didukung parser dan batas ukuran file.
- Kontrak API token sementara, autentikasi service Python, timeout, retry policy, dan antivirus scanner.
- Daftar dokumen wajib per PB/PD/stage dan aturan kondisi final.
- Definisi detail actor/unit scope untuk semua workflow category selain drawing.
- Retensi file dan jadwal arsip resmi.
- Format output Auto MTO dan daftar simbol/KHS yang tervalidasi.
- DDL v3.2.1 adalah baseline desain yang telah diaudit secara statis. Eksekusi PostgreSQL runtime masih menunggu dijalankan pada PostgreSQL lokal pengguna; migration Laravel belum dibuat.
