## B. Koreksi yang diterapkan pada baseline

1. Unique partial expression index mencegah duplikasi rule aktif dengan key identik dalam satu template.
2. Unique `(package_id, sequence_number)` mencegah urutan dokumen ganda dalam satu paket.
3. Partial unique `(package_id) WHERE is_primary=true` membatasi satu dokumen utama per paket.
4. Actor snapshot divalidasi terhadap workflow stage sumber, role, unit scope, `decision_required`, dan `minimum_approvals`.
5. Extraction membawa `package_id`; trigger mencocokkan paket dengan result/attempt/job-file lineage.
6. Item source menggunakan composite FK untuk memastikan item dan extraction berasal dari paket sama.

## C. Pemeriksaan dependency

DDL T4.2.4 mereferensikan tabel fondasi, aplikasi, material, satuan, KHS, dan BOM. DDL tidak membuat ulang `users`, `roles`, `organizational_units`, `applications`, `materials`, `units_of_measure`, `khs_items`, `khs_item_versions`, `bom_headers`, `bom_items`, atau `bom_formula_definitions`.

Tipe dependency yang diasumsikan: UUID untuk PK di atas kecuali `roles.id` BIGINT. Struktur rinci tetap harus dibandingkan dengan migration final T4.2.1–T4.2.3 ketika tersedia.

DDL dijalankan pada database disposable `distriva_t424_test` menggunakan PostgreSQL 18.6 dan dependency contract fixtures. Database berisi 53 tabel: 32 T4.2.4 dan 21 dependency fixture.

- Runner setup dan DDL: PASS.

Detail setiap negative check dan SQLSTATE ada di `docs/28-T4.2.4-POSTGRESQL-TEST-PLAN.md` dan bukti runtime di `test-evidence/2026-11-05-t424-runtime.md`.

Catatan mekanisme: `previous_version_id` lintas dokumen ditolak oleh guard trigger `trg_document_version_chain` dengan `P0001` sebelum composite FK dievaluasi. Integritas berhasil dijaga; test plan diperbarui agar sesuai perilaku aktual.

## E. Batas validasi

Fixture adalah contract-minimal test-only; bukan migration produksi dan bukan schema penuh T4.2.1–T4.2.3. Runtime test membuktikan integrasi DDL T4.2.4 dengan kontrak FK yang disiapkan fixture, bukan kompatibilitas dengan migration final upstream.

Belum diuji:
- Policy Laravel reviewer terhadap `user_role_assignments`, role aktif, scope unit, dan masa berlaku.
- Idempotency callback Python.
- Queue retry dan recovery per file.
- Integrasi terhadap migration final T4.2.1–T4.2.3.
- Pemilihan workflow lintas template berdasarkan effective date/priority.
- Transaksi atomik pada service aplikasi upload version + current pointer + review cycle.

Database disposable `distriva_t424_test` dipertahankan untuk inspeksi; jangan dipakai sebagai development atau production database.

## F. Kesimpulan

**PASS — DDL T4.2.4 lulus runtime integration test terbatas di PostgreSQL 18.6 dengan contract-minimal dependency fixtures.**
