## Addendum — root cause of the false WhatsApp failure
Owner's re-run printed: `rincian: ... HTTP 200, 'success' is true (expected '1'); top-level keys: [success, data, message]`. The gateway answer was correct. Bug: Laravel `env()` parses `SUCCESS_VALUE=true` into boolean true; the driver cast it with `(string)` to '1' and compared with 'true'. Fix: canonical comparison on both sides. Tests: 198 / 700 assertions PASS — 12-case data provider (env boolean vs JSON bool/int/string, false values, status text, missing, array) and a regression that loads a real `.env` file through Dotenv and asserts both `env() === true` and `(string) === '1'`. Why the old tests missed it: they set config values as strings and never went through .env parsing.
Check with the owner's real config and a faked Starsender answer (no network): accepted as success.
NOT verified: a new real send after the fix (owner to re-run distriva:notify-test).
