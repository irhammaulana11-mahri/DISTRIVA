## Addendum — "cannot log in" investigation (2026-11-06)
Symptom: owner could not use the app; the owner's account had no login attempt at all (failed_login_attempts=0, no tokens, last_login_at NULL). Findings: a foreign service owns 0.0.0.0:8000 and answers plain-text `404 - Not Found` / `400 - Bad Request`; the owner's `php artisan serve` therefore moved to 127.0.0.1:8001 automatically, while Vite still proxied `/api` to 8000, so every login request hit the foreign service and never reached Laravel. Not an application defect.
Fix: `vite.config.js` now reads `VITE_API_PROXY` via `loadEnv` (frontend/.env.local, git-ignored; .env.example added); `.env.local` set to http://127.0.0.1:8001. Vite restarted itself. Verified through the owner's running Vite (5173): `/api/me` -> 401 JSON from Laravel; bogus login -> 401 generic message (no data changed). Vitest 25/25 and build PASS.
NOT verified: the owner's own login (temporary password unknown to me), the UI after login.
