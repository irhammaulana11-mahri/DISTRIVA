## Concurrency and rollback

Three concurrent uniqueness checks were run using separate PostgreSQL sessions:

| Entity | Result |
|---|---|
| Document version number | One insert committed; competing insert rejected; one row remains |
| Review cycle number | One insert committed; competing insert rejected; one row remains |
| Package number/version | One insert committed; competing insert rejected; one row remains |

A transaction inserted a document version and then failed to create its review cycle due to an invalid workflow-template FK. The transaction rolled back and the version row was absent: **PASS**.

## Execution notes and limits

- The first runner attempt found an incorrect relative DDL path; `DOCS_DIR` was corrected in `05-run-test-suite.sh` before the successful run. The packaged runner is corrected to resolve `docs/` from the repository root.
- A first draft of the negative test setup hit a duplicate job-file key before the intended FK. The test data was corrected and the clean rerun passed all 17 checks.
- Laravel reviewer policy, Python callback idempotency, queue retry behavior, and per-file recovery are **NOT RUN** because the application/service implementations are not present.
- The fixture schema is contract-minimal and does not validate all T4.2.1–T4.2.3 domain rules. This result is not production migration approval.
- No migration was run on `distriva_db`; all runtime DDL and fixtures were applied only to `distriva_t424_test`.

## Conclusion

**PASS — T4.2.4 PostgreSQL DDL/constraint integration test** on PostgreSQL 18.6 using contract-minimal T4.2.1–T4.2.3 dependency fixtures.

This result does not establish full application integration, upstream migration compatibility, or production approval.
